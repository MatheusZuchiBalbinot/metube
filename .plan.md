## Parte 1 — Component Tests (Crítico)

### Diagnóstico Atual

- **166 testes passando** — todos em Redux slices e utils (camada lógica pura)
- **0 testes de componente** — nenhum componente React é testado
- **Cobertura ~8%** — precisa subir para ~40%+
- **Vitest config** precisa de ajustes: glob só aceita `*.test.ts` (não `.tsx`), e faltam aliases (`@components`, `@ui`, `@pages`, `@styles`) no bloco `test.alias`

### Pré-requisitos (Infraestrutura de Teste)

Antes de escrever qualquer teste de componente, preciso:

#### 1. Instalar `@testing-library/react` + `@testing-library/jest-dom`

```bash
npm install -D @testing-library/react @testing-library/jest-dom
```

Essas são as libs padrão para testar componentes React. RTL (React Testing Library) renderiza componentes em jsdom e fornece queries acessíveis (`getByRole`, `getByText`). `jest-dom` adiciona matchers como `toBeInTheDocument()`, `toBeVisible()`.

#### 2. Atualizar `vite.config.ts` — bloco `test`

```typescript
test: {
    environment: 'jsdom',                    // ← mudar de 'node' para 'jsdom' como padrão
    include: ['tests/**/*.test.{ts,tsx}'],   // ← aceitar .tsx
    setupFiles: ['tests/setup.ts'],          // ← setup global
    alias: {
        // adicionar os que faltam:
        '@components': resolve(__dirname, 'src/components'),
        '@ui': resolve(__dirname, 'src/components/ui'),
        '@pages': resolve(__dirname, 'src/pages'),
        '@styles': resolve(__dirname, 'src/styles'),
        // manter os existentes:
        '@data': ..., '@utils': ..., '@hooks': ...,
        '@store': ..., '@models': ..., '@context': ...,
    },
},
```

**Trade-off:** Mudar o environment default para `jsdom` pode tornar os testes de utils ~10% mais lentos. Porém simplifica tudo — não precisa mais do pragma `// @vitest-environment jsdom` em cada arquivo. Os testes de utils já usam jsdom em alguns casos, então o impacto é mínimo.

#### 3. Criar `tests/setup.ts` — setup global

```typescript
import '@testing-library/jest-dom/vitest';
```

Registra os matchers do jest-dom globalmente.

#### 4. Criar `tests/helpers/renderWithProviders.tsx` — wrapper de teste

Componentes como `VideoCard`, `Header`, `Guard` dependem de:
- **Redux store** (`useAppSelector`, `useAppDispatch`)
- **React Router** (`useNavigate`, `NavLink`, `Navigate`)
- **i18next** (`useTranslation`)
- **SearchContext** (`useSearch`)

O wrapper vai criar um store preconfigurado + providers:

```typescript
function renderWithProviders(
    ui: ReactElement,
    options?: {
        preloadedState?: Partial<RootState>,
        route?: string,
    },
) {
    const store = configureStore({
        reducer: { video, theme, auth, toast, subscription, playlist, search },
        preloadedState: buildState(options?.preloadedState),
    });

    return render(ui, {
        wrapper: ({ children }) => (
            <Provider store={store}>
                <MemoryRouter initialEntries={[options?.route ?? '/']}>
                    <SearchProvider>
                        {children}
                    </SearchProvider>
                </MemoryRouter>
            </Provider>
        ),
    });
}
```

**i18n:** O `i18next` já está configurado globalmente em `src/i18n/index.ts` — basta importá-lo no setup.ts para que `useTranslation` funcione nos testes sem mock.

#### 5. Reutilizar helpers existentes

Os testes de slice já têm `makeVideo()`, `makeState()`, `vid()`, `chId()`, `t()`. Vou extraí-los para `tests/helpers/factories.ts` para reusar nos testes de componente.

## Parte 2 — Otimizações (Média prioridade)

### 2A. HLS Streaming (Player)

#### Diagnóstico

O player atual usa `<video src={url}>` direto — funciona para MP4 mas não suporta:
- Adaptive bitrate (qualidade automática por conexão)
- Múltiplas resoluções (360p, 720p, 1080p)
- Live streaming
- Seek eficiente em vídeos longos

#### Plano

**Instalar `hls.js`** (~50KB gzipped) — biblioteca padrão para HLS no browser:

```bash
npm install hls.js
```

**Criar `hooks/useHls.ts`** — hook que conecta hls.js ao `<video>` element:

```typescript
export function useHls(videoRef: RefObject<HTMLVideoElement>, src: string) {
    const hlsRef = useRef<Hls | null>(null);

    useEffect(() => {
        const video = videoRef.current;
        if (!video) return;

        // Se o browser suporta HLS nativo (Safari), usa direto
        if (video.canPlayType('application/vnd.apple.mpegurl')) {
            video.src = src;
            return;
        }

        // Se não é .m3u8, usa src direto (MP4 fallback)
        if (!src.endsWith('.m3u8')) {
            video.src = src;
            return;
        }

        // HLS.js para browsers que não suportam nativo
        const hls = new Hls({ startLevel: -1 }); // -1 = auto quality
        hls.loadSource(src);
        hls.attachMedia(video);
        hlsRef.current = hls;

        return () => { hls.destroy(); hlsRef.current = null; };
    }, [src, videoRef]);

    return {
        // Expor níveis de qualidade para o PlayerSettings
        get levels() { return hlsRef.current?.levels ?? []; },
        setQuality(levelIndex: number) { hlsRef.current?.currentLevel = levelIndex; },
    };
}
```

**Alterar `player.tsx`** — substituir `<video src={src}>` pelo hook:

```diff
- <video ref={videoRef} src={src} />
+ // useHls gerencia o src automaticamente
+ const hls = useHls(videoRef, src);
+ <video ref={videoRef} />
```

**Alterar `PlayerSettings`** — adicionar seletor de qualidade usando `hls.levels`.

**Compatibilidade retroativa:** Se `src` for MP4 (não `.m3u8`), o hook faz `video.src = src` direto — zero breaking changes.

**Mesma abordagem para `shortPlayer.tsx`** — usa o mesmo `useHls` hook.

### 2B. PWA Support

#### Diagnóstico

Zero infraestrutura PWA existe — sem manifest, sem service worker, sem vite-plugin-pwa.

#### Plano

**Instalar `vite-plugin-pwa`** — integração automática com Vite:

```bash
npm install -D vite-plugin-pwa
```

**Configurar em `vite.config.ts`:**

```typescript
import { VitePWA } from 'vite-plugin-pwa';

plugins: [
    // ... existentes
    VitePWA({
        registerType: 'autoUpdate',
        manifest: {
            name: 'Video Summarizer',
            short_name: 'VidSum',
            theme_color: '#7c3aed',   // violet accent
            background_color: '#0f0f0f',
            display: 'standalone',
            icons: [
                { src: '/icon-192.png', sizes: '192x192', type: 'image/png' },
                { src: '/icon-512.png', sizes: '512x512', type: 'image/png' },
            ],
        },
        workbox: {
            globPatterns: ['**/*.{js,css,html,ico,png,svg,woff2}'],
            runtimeCaching: [
                {
                    urlPattern: /^https:\/\/picsum\.photos\/.*/i,
                    handler: 'CacheFirst',           // thumbnails
                    options: { cacheName: 'thumbnails', expiration: { maxEntries: 200 } },
                },
            ],
        },
    }),
],
```

**Criar ícones** — `public/icon-192.png` e `public/icon-512.png`.

**O que isso dá automaticamente:**
- Install prompt ("Add to Home Screen")
- Offline shell (app carrega mesmo sem internet, dados ficam em Redux/localStorage)
- Cache de assets estáticos (JS, CSS, fontes)
- Cache de thumbnails (runtime caching)
- Auto-update quando nova versão é deployada

### 2C. Analytics (Lightweight)

#### Diagnóstico

Não há tracking de uso. Para entender como os usuários usam o app, precisamos de analytics básico.

#### Plano

**Abordagem: Custom events + localStorage** (sem dependência externa).

**Criar `utils/analytics.ts`:**

```typescript
interface AnalyticsEvent {
    event: string
    data?: Record<string, string | number>
    timestamp: number
}

const BUFFER: AnalyticsEvent[] = [];
const FLUSH_INTERVAL = 30_000; // 30s

export function track(event: string, data?: Record<string, string | number>) {
    BUFFER.push({ event, data, timestamp: Date.now() });
}

export function flushAnalytics() {
    if (BUFFER.length === 0) return;
    const batch = BUFFER.splice(0);
    // Quando backend estiver pronto: POST /api/analytics
    // Por agora: salva em localStorage para análise manual
    const existing = JSON.parse(localStorage.getItem('analytics') ?? '[]');
    localStorage.setItem('analytics', JSON.stringify([...existing, ...batch].slice(-500)));
}

// Auto-flush a cada 30s
setInterval(flushAnalytics, FLUSH_INTERVAL);
window.addEventListener('beforeunload', flushAnalytics);
```

**Eventos a trackear:**

| Evento | Onde | Dados |
|--------|------|-------|
| `video.play` | Player onPlay | `{ videoId }` |
| `video.complete` | Player onEnded | `{ videoId, duration }` |
| `video.like` | useVideo.likeVideo | `{ videoId }` |
| `search.query` | Header search submit | `{ query, resultCount }` |
| `page.view` | Router location change | `{ path }` |
| `filter.apply` | FilterPanel onChange | `{ tags, sortBy }` |

**Criar `hooks/usePageView.ts`:**

```typescript
export function usePageView() {
    const location = useLocation();
    useEffect(() => {
        track('page.view', { path: location.pathname });
    }, [location.pathname]);
}
```

**Chamar `usePageView()` em `AppLayout`** — captura todas as navegações.

## Riscos e Mitigações

| Risco | Mitigação |
|-------|-----------|
| `rolldown-vite` incompatível com `vite-plugin-pwa` | PWA é a parte menos crítica — pode ser adiada se der conflito |
| `hls.js` aumenta bundle size (~50KB) | Lazy import: `const Hls = (await import('hls.js')).default` |
| Testes de componente lentos com jsdom | jsdom já está em uso; RTL é otimizado para isso |
| `@testing-library/react` incompatível com React 19 | RTL v16+ suporta React 19 oficialmente |
| CSS imports quebram testes | Vitest ignora CSS por padrão — sem problema |
